## Step 2 · Frame the meeting (5 min)

**Say this plainly, up front:**

> We are not looking to create a plan for every marginal or partially accessible purchase the
> Library makes. A formal plan is for barriers severe enough to stop someone doing something
> essential. What is missing is everything that should sit *before* that point, and that is
> what we are here to build.

Then name the three outcomes and the scope: **web and mobile ICT the Library regularly
procures.** Not print, not the whole collection, not retroactive conversion.

## Step 3 · What already exists (5 min)

**Purpose:** make clear they are joining something, not building it.

**Say this:**

> The campus already has an established process for alternate access. The problem is that
> every part of it is TAAP machinery, and all of it is owned by ATI. The indicator behind it
> asks for three things — when a plan is required, who is responsible, and how it gets
> distributed — and the Library appears in none of them. That is why everything ends up as a
> TAAP: it is currently the only route that exists.

> The same is true for ticketing. There is already a service-catalog routing process for
> accessibility requests. We need a Library route inside it, not a new system.

## Step 4 · The four elements (25 min) — the core of the meeting

### 4A · Classifying barriers (7 min)

**Explain:** we decide whether a barrier is severe by asking whether it stops an essential
function. So we need your definition of essential, not ours.

- What are the **essential functions** of a library resource? *(prompt if needed: search,
  retrieve the full text, read it, export a citation)*
- Which of those does a **keyboard-navigation failure** break? *(This is the live blocker on
  the pending requests.)*
- Give me an example of a barrier you would want approved **without** a plan.

### 4B · Standing alternatives per barrier class (10 min)

**Explain:** if there is a documented route for a class of barrier, an individual plan is not
needed. Four classes. For each: what is the route, who does it, how long does it take.

- **Text** — untagged PDFs, no OCR. Route? Who? Turnaround? Roughly how many a year?
- **Video and audio** — uncaptioned media. **Is there any route today at all?**
- **Interactive** — search widgets, viewers, embedded tools. Any route, or is referral the
  only honest answer?
- **Images and charts** — described by whom?

Then, for each: **can a student get this without having to ask a person?**

> Worth flagging aloud: a route you can only reach by asking counts as a lesser category
> legally. That is fine — we just have to record it accurately rather than overclaim.

### 4C · Notice at the point of access (5 min)

**Explain:** a route nobody can find does not count. The places these resources are reached
are Library pages, so this part only the Library can do.

- Which pages are the real points of access?
- Who edits them?
- Who is the **named contact** a user is sent to?
- In the ticketing system: what category should a library access problem use, and who triages
  it? Does it reach the alternate-format person directly?

### 4D · Getting vendor documentation earlier (3 min)

**Explain:** "no VPAT available" is its own trigger for a formal plan. Asking sooner removes
it entirely.

- Who talks to vendors, and when in the selection cycle?
- Could the VPAT be requested **before** the requisition is raised?
- Does this apply to renewals as well as new purchases?

## Language habits for the recording

- Spell each name once, aloud
- Say each system's full name the first time: *"For the record, the system is called…"*
- Tag as you go: **"Action item:"** · **"Open question:"** · **"Decision:"**
- Repeat numbers with units: *"about forty requests per semester"*
- Say **"we will"** for a commitment and **"it would be good if"** for a wish — only the first
  becomes a plan
